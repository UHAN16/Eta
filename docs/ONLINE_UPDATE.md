# Eta 在线升级

## 使用

1. 打开 **设置 → 关于 → 在线升级**，检查当前渠道。
2. 发现新版后点击 **下载并安装**。Eta 会显示下载进度，并先验证安装包。
3. 首次使用时，如果 Android 要求，给 Eta 开启「允许来自此来源」。返回后，在 Android 安装界面点击「更新」。Eta 不会静默安装，也不会更改设备其他来源的权限。

升级只支持签名一致、包名一致、版本号更高的安装包。官方版、旧调试版和自签名版不能跨签名覆盖；不要为了切换签名而直接卸载有重要资料的版本。应用内更新和 GitHub 构建 / 分支同步是两件事。

## 发布渠道

默认查询 **UHAN16/Eta** 的 GitHub 最新正式 Release。该仓库尚无正式 Release 时，App 会明确提示，不会改用原作者发布的安装包（另一个渠道无法保证保留定制功能）。

维护自定义渠道时，在构建时设置 Gradle 属性 `eta.updateRepository=Owner/Repo`。将 Release 正式发布，不使用草稿、预发行、Actions 临时产物；版本三个数字段，例如标签 `v4.0.1`。APK 资产按照当前构建规范命名为 `Eta-v4.0.1.apk`，APK 的 `versionName` 为 `4.0.1`，且相对于旧版递增 `versionCode`。发布 APK 必须用相同发布密钥签名，GitHub 必须提供实际资产大小和 `sha256:` 摘要。

应用内下载使用固定仓库路径和 HTTPS，只跟随 GitHub 资产服务的重定向。校验资产大小、SHA-256、包名、版本、设备最低系统要求以及当前 APK 签名，失败不交给系统安装器。仅在用户主动操作后下载，不后台轮询；下载文件在私有缓存中，只把校验成功的单个文件临时授权给系统安装流程。发布密钥不包含在仓库、更新元数据或安装包内。
