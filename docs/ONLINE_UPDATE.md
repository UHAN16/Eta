# Eta 在线升级

## 使用

1. 打开 **设置 → 关于 → 在线升级**，检查当前渠道。
2. 发现新版后点击 **下载并安装**。Eta 会显示下载进度，并先验证安装包。
3. 首次使用时，如果 Android 要求，给 Eta 开启「允许来自此来源」。返回后，在 Android 安装界面点击「更新」。Eta 不会静默安装，也不会更改设备其他来源的权限。

升级只支持签名一致、包名一致、版本号更高的安装包。官方版、旧调试版和自签名版不能跨签名覆盖；不要为了切换签名而直接卸载有重要资料的版本。应用内更新和 GitHub 构建 / 分支同步是两件事。

## 发布渠道

从 **3.4.7** 起默认查询 **Gitee a962327460/eta** 最新正式 Release。无正式 Release 时明确提示，不会自动切换到 GitHub 或原作者渠道。3.4.5 已安装版本仍查询 GitHub，首次迁移需要手动安装同签名的 3.4.7；新版本保留原数据，后续从 Gitee 检查更新。

维护自定义渠道时，在构建时设置 `eta.updateProvider=gitee` 或 `github`，以及 `eta.updateRepository=Owner/Repo`。渠道固定在构建内，下载的元数据不能指定其他仓库。版本标签必须为三个数字段，例如 `v4.0.1`，对应 `Eta-v4.0.1.apk`，APK 的 `versionName` 为 `4.0.1`，`versionCode` 严格递增，并使用相同发布密钥签名。

Gitee 仓库必须公开；客户端不携带令牌。只查询正式 Release，并从独立的 `attach_files` 接口核对唯一附件的 ID、名字、大小和完整下载地址。Release 正文必须包含唯一的校验块（其中大小和摘要必须来自实际签名 APK）：

````text
```eta-update
{"schema":1,"name":"Eta-v4.0.1.apk","size":12345678,"sha256":"64位十六进制SHA256"}
```
````

缺失、重复、格式错误、大小不一致或附件列表可能不完整时，不提供应用内安装。GitHub 渠道仍要求 GitHub 提供实际资产大小和 `sha256:` 摘要，不使用 Gitee 正文替代 GitHub 资产校验。

应用内下载使用固定仓库路径和 HTTPS。Gitee 仅允许重定向到当前仓库的准确附件路径及 `foruda.gitee.com/attach_file/<数字>/<原文件名或其全小写形式>`；GitHub 仍仅允许其原有资产服务。两个渠道的重定向白名单不混用。校验资产大小、SHA-256、包名、版本、设备最低系统要求以及当前 APK 签名，失败不交给系统安装器。仅在用户主动操作后下载，不后台轮询；下载文件在私有缓存中，只把校验成功的单个文件临时授权给系统安装流程。

## 发布工具

`scripts/publish-gitee-release.py` 从进程环境 `GITEE_TOKEN` 读取维护者授权，仅用于 Gitee API，不写入 Git、日志、校验块或 APK，也不发送到下载/CDN。参数见 `--help`：需要新 APK、前一个正式 APK、说明文本、`aapt` 和 `apksigner`。工具先核对包名、版本递增和签名一致，校验本地与远程标签指向，再建立预发行、上传附件，通过无登录元数据及完整下载 SHA-256 校验后才转为正式发布。中断可重新运行，不覆盖已有同名但不同内容的附件或说明。

匿名接口限流或下载失败时保持预发行，不降低校验、不把令牌装进客户端。发布密钥始终保留在仓库外。实际 Android 更新确认和手机音频效果仍需真机验收。
